# dsh-model-organizer

给 DSH（DeepSeek Harness）换个更好用的模型选择器：**按供应商分组、可折叠、可拖拽排序**。

## 它解决什么问题

官方那个模型下拉是一个扁平长列表——供应商只是粘性小标题，模型多的时候要滚很久，也没法按自己的习惯排序。这个插件把它改成两级：**根层先选「模型」或「推理等级」，模型层里按供应商分组**，供应商和模型的顺序都能直接拖。

## 功能

### 聊天框的模型菜单
- 根层与官方一致：「模型」「推理等级」两个入口（「推理等级」常驻，模型未声明等级时置灰）
- 「模型」按供应商分组、可折叠，顺序与设置页浮窗一致；当前模型加粗
- 模型多于 4 个时出现官方同款的「搜索模型」框
- 外观完全沿用官方菜单（同一表面、同一套图标、同一毛玻璃背景）

### 设置页「模型」：本插件接管
- 设置里**始终只有「模型」一行**，点开就是本插件的页；每次打开设置都默认回到本页
- 交还官方页：本页标题右侧的「官方模型页」= 这一次打开期间交还；官方页右下角浮窗里的「模型管理页」= 再接管回来
- 左栏：置顶只读的「官方（内置）」路由（点击切回官方页）+ 自建供应商（分「官方目录 / 自定义供应商」，可拖动排序，顺序只记本机）
- 右栏：API 地址、API 格式（三种协议）改动即时保存；密钥写入凭据库（读不回明文，可清除）
- 模型列表一行一个：**整行可拖动排序**，**单击打开「模型详情」**——ID、显示名、上下文窗口、最大输出、输入模态、推理等级、启用/删除；保存立即写回 DSH 配置
- 「获取可用模型」：调官方发现接口（目录里已有的供应商不联网，自己加的网关才问 `GET {baseURL}/models`），弹窗可搜索、全选，**勾选后点「添加所选」才写回**
- 左栏末尾虚线框「**+ 添加模型提供商**」：路由 ID、显示名、API 地址、格式、密钥、**至少一个模型 ID**；ID 校验非空/字符集/重名，配置与密钥引用一次写入
- 删除供应商：详情右上角垃圾桶，先确认；删配置并清理本页派生的密钥引用（别处配置的密钥不动），官方路由没有这个按钮
- 每行的**绿点就是启用开关**：亮=出现在本插件菜单，暗=从本插件菜单移除；**DSH 配置原样保留**，状态存本机

### 排序、按钮与细节
- 设置页右下角浮窗：**直接拖动**供应商行/模型行排序；模型顺序写进 DSH 配置（同一份配置的所有设备共用），供应商顺序与浮窗位置只记在当前浏览器
- 页面上所有按钮（含所有弹窗）都有**悬停反馈**：普通按钮提亮、主要操作保持强调色、危险操作泛红、开关用光环（不改开/关底色，避免被误读为状态变化）
- 模型行两颗图标键：🔗 **测速**（问网关该模型在不在列表里，结论 ✓/⚠/✗ 变色）、🗑 **删除**；两者同尺寸，测速键是普通按钮的浅底，删除键是红框
- 悬停文案只说明「这个按钮做什么 / 现在什么状态」，不写实现细节

## 安装

装到哪个环境，就用对应的方法：

**浏览器版（`web`，CLI 管理）**

```sh
dsh plugin --profile web add @nimoxie/dsh-model-organizer
```

装完重启服务（关掉再 `dsh web`）。`--profile` 后面是目标 profile 名：浏览器版是 `web`，你自己另外创建的 profile 填对应的名字。

**桌面客户端**

桌面 profile 由客户端独占管理，**不要用上面的 CLI 命令**。请在客户端的「插件管理」页添加本包（包名 `@nimoxie/dsh-model-organizer`）。

卸载（CLI 环境）：

```sh
dsh plugin --profile <profile> remove @nimoxie/dsh-model-organizer
```

开发用：从 GitHub 或本地目录装

```sh
dsh plugin --profile <profile> add github:NimoXie15/dsh-model-organizer
dsh plugin --profile <profile> add link:/absolute/path/to/dsh-model-organizer
```

> **兼容性**：已在 DSH `0.1.7`、`0.2.0-rc.1`（web）、`0.2.0-rc.2`、`0.2.1-rc.2`（桌面端）上核验，`0.1.5` 起都可用。
>
> 升级插件后如果界面没变化，按 **Ctrl+Shift+R** 强刷一次（浏览器可能还在用缓存的旧版本）。

## 想让「推理等级」可用，需要模型自己声明

「推理等级」入口常驻菜单根层；只有模型声明了等级，它才可点、才会在按钮上显示当前等级。

0.5.0 起在「模型详情」弹窗里直接设置：推理等级选「继承」（沿用该模型已有的声明）、「不支持」，或「自定义」——自定义时逐行添加等级，**键 = 菜单里显示的等级，值 = 选中时发给模型的 API 参数**（只有 `off` 可以留空）。

也可以直接在 profile 配置里给这个模型声明（0.2.x 在 `cordis.patch.yml`，0.1.x 在 `settings.yaml`）：

```yaml
# 该供应商的 models[] 条目（0.2.x 在 profile 的 cordis.patch.yml；0.1.x 在 settings.yaml）
- id: <你的模型 ID>
  reasoningEfforts:      # 键=菜单里显示的等级，值=选中时发给模型的 API 参数；只有 off 可以留空
    off:
    high: high
```

## 已知限制

- 「测试连接」验证的是**地址 / 密钥 / 网关可达性，以及这个模型 ID 是否在网关返回的列表里** —— 它不会真的发一条消息给模型（DSH 的远程接口没有这个能力，客户端也读不回密钥）。所以「✓」只代表这条路由和这个 ID 是通的，不等于这个模型一定能补全
- 设置页右下角的排序浮窗**只列你自己添加的供应商**（写进配置的那些），官方路由**根本不进这个浮窗**；想在左栏看到官方路由，看顶部只读的「官方（内置）」分组
- 浮窗里排出的供应商顺序会**镜像**到官方模型页的卡片上；官方卡片（DeepSeek 官方等）被刻意保持在最前面
- 供应商顺序、浮窗位置只存在当前浏览器；模型顺序存在 DSH 的用户配置里，同一份 DSH 配置的所有设备共用——两台机器各装一份 DSH 则互不相通
- 不修改 DSH 本体，只通过官方提供的扩展点接入
